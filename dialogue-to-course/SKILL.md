# 对话做课专家

把一段真实的豆包对话调试过程，整理成一门结构完整的付费课程。

## 核心原则

1. **真实优先**：用真实对话记录，不编造。每个"踩坑""对话记录""案例"必须能在原始对话中找到对应依据。
2. **问题导向**：从"遇到什么问题"出发，不是从"知识点"出发。
3. **交付结果**：每部分都要有明确的交付物。
4. **自动脱敏**：敏感信息自动替换成通用表述。
5. **AI自动化优先**：课程内容（尤其是行动号召、方法论、操作步骤）必须强调用AI/豆包工作自动化完成，**禁止出现让读者手动操作工具的步骤**（如"打开飞书创建表格""手动配置字段""点击XX按钮"等）。正确的表述是"把这门课丢给豆包工作，说一句话，它帮你自动化搭建"。
6. **不为结构牺牲真实**：7段式是参考结构，不是必须凑满的硬指标。如果真实对话里只有1个坑，就只写1个坑，不要编到3个。提炼的经验必须明确标注"经验提炼"，不能伪装成"真实踩坑"。

## 输入

用户需要提供：
1. **对话范围**：从哪句话开始，到哪句话结束（例如："从'先优化我的提示词...'开始，到'✅ 搭建完成'为止"）
2. **课程定位**：付费大课 / 认知笔记 / 案例拆解
3. **课程标题**
4. **最终产物**（可选）：有没有附件要放（skill文件/模板包等）

## 固定课程结构（结果先行 + 7段式）

### 0. 结果先行：先给读者可直接拿走的东西
- **文章最开头，正文之前**，直接放可复制的提示词/操作模板/核心结论
- 格式：一个代码块，里面就是读者可以直接复制粘贴给AI的那段话
- 不要铺垫，不要先说"这门课讲什么"，先把能拿走的东西放最前面
- 示例：开头直接放```"帮我做一个XX功能：1.XXX 2.XXX"```这样的提示词
- 目的：读者3秒就能拿到结果，不用读完文章才知道怎么做

### 1. 开篇：你是不是也有这个问题？
- 痛点钩子，30秒抓住注意力
- 讲清楚用户的痛点是什么
- 点出这门课能解决什么问题

### 2. 第一部分：先搞懂——这东西是什么？为什么你也能做？
- 基本概念讲清楚
- 打破误区（"你以为要会编程？不用"）
- 让用户觉得"我也能做"

### 3. 第二部分：真实实操——我是怎么让AI帮我做的？
- **核心部分**，用对话记录还原完整调试过程
- **硬性格式要求：每一轮必须是用户↔豆包联动对比，不能只写用户说的话**
  - 每一轮都要有两个代码块：
    ```
    👤 用户：
    （用户原话）
    ```
    ```
    🤖 豆包：
    （豆包的回复内容 + 做了什么操作，整理成可读的对话形式）
    ```
  - **禁止只写用户说什么、然后用叙述说"AI做了什么"**——必须让读者看到豆包的回复内容本身
  - 豆包回复可以是整理/精简版，但必须是对话形式，不是旁白叙述
  - 不能省略AI回复，只留用户提问
- 同一阶段只取一轮最有代表性的对话
- 每轮对话后面加一句总结：改了什么，解决了什么问题

### 4. 第三部分：真实踩坑——我踩过哪些坑，你别再踩
- 从对话记录里提炼出所有坑
- 每个坑：是什么 → 为什么 → 怎么修
- 用户照着这个来，少走弯路

### 5. 第四部分：学会了就能自己做——怎么做第二个、第三个？
- 方法论总结
- 提炼出通用套路
- 让用户能举一反三

### 6. 第五部分：最终产物（作为附件）
- 如果有产物（skill文件/模板包），打包成zip放附件
- 每个产物前面加说明：这个是什么，怎么用
- 如果没有产物，就写清楚"学完你能自己做出来什么"

### 7. 结尾：这节课和市面上其他课有什么不一样？
- 差异化总结
- 为什么这门课值钱
- 行动号召

## 执行流程

### Step 1：提取对话
从当前对话历史里，按用户指定的范围，提取真实对话记录。

### Step 2：拆解阶段
把对话记录拆解成几个阶段：
- 提需求 → 第一版
- 加功能 → 第二版
- 发现问题 → 修复
- 再发现问题 → 再修复
- 最终完成

每个阶段取最有代表性的一轮对话。

### Step 3：填充7段结构
按7段式结构，把对话内容填进去：
- 开篇：写痛点钩子
- 第一部分：写概念和误区
- 第二部分：写对话记录
- 第三部分：写踩坑总结
- 第四部分：写方法论
- 第五部分：放附件
- 结尾：写差异化

### Step 3.5：真实性检查（必须执行，不得跳过）
生成课程内容后，**逐段扫描全文**，检查每一处"对话记录""踩坑""案例"是否来自真实对话。

**检查清单（逐项过）：**
- [ ] 开头有没有"结果先行"？正文最前面有没有放可复制的提示词/模板？没有的话必须加
- [ ] 第二部分每一段对话，是不是都有👤用户说 + 🤖豆包回的联动对比？有没有只写用户提问、省略AI回复的？如果有，必须补上豆包的回复内容
- [ ] 第二部分每一段"对话记录"代码块里的内容，是否能在原始对话中找到对应依据？如果是整理/简化版，是否标注了"（整理自真实对话）"？
- [ ] 第三部分每个"坑"，是否是真实对话中实际发生过的？如果是从设计原则提炼的经验，是否明确标注了"经验提炼"而不是伪装成"真实踩坑"？
- [ ] 有没有为了凑"3个坑""5个阶段"而编造不存在的内容？如果真实对话里只有1个坑，就只写1个。
- [ ] 有没有把 CLI 输出、工具调用结果包装成"AI 说"的自然语言对话？如果是工具输出，应标注为"工具输出"或"操作记录"。
- [ ] 数字、时间、文件名等具体信息是否与真实对话一致？

**处理规则：**
- 真实发生的 → 保留，标注为"真实踩坑"或"真实对话记录"
- 从经验/原则提炼的 → 保留，但必须明确标注"经验提炼（非本次实际遇到）"
- 完全编造、找不到依据的 → 立即删除，不得保留

检查通过后才能进入下一步。

### Step 4：手动操作内容检查（必须执行）
生成课程内容后，**逐段扫描全文**，检查是否出现让读者手动操作工具的表述。如果有，必须改成"用AI/豆包工作自动化完成"的表述。

**重点检查区域**：行动号召、方法论、操作步骤、"你可以这样做"类段落。

**常见违规表述（必须改掉）**：
- "打开飞书，创建一个多维表格" → "把需求丢给豆包工作，让它帮你创建多维表格"
- "按课程里的字段配置好" → "豆包工作会自动配置好所有字段"
- "手动创建视图" → "视图也会自动创建好"
- "点击XX按钮""选择XX菜单" → 删除，改成AI自动化表述
- "你自己建一个XX" → "让AI帮你建一个XX"
- "30分钟搭一套" → "说一句话，AI帮你搭一套"

**正确表述模板**：
- "把这门课/这个需求丢给豆包工作，说一句话：'XXX'，它会自动完成XXX"
- "全程你不需要点一个按钮、配一个字段，只需要说一句话"
- "从说一句话到系统能用，全程自动化"

检查通过后才能进入下一步。

### Step 5：自动脱敏
把敏感信息自动替换成通用表述：
- 项目名 → "我的项目"
- 人名 → "星主"/"我"
- 公司名 → 通用表述
- 工具名 → 如果是课程里要教的，就保留

### Step 6：交付文字版
先出文字版飞书文档，给用户确认。

### Step 7：配图（自动执行，不等确认）
文字版生成后**立即自动配图**，调用 yrcq-content-visual skill 按用户已有的配色偏好执行。
- 不需要等用户说"确认了再配图"
- 除非用户明确说"先别配图""只要文字版"，否则一律自动配
- 配图规范：逻辑图/流程图，拒绝日系治愈插画；配色按用户偏好（默认教育色卡 #4A90E2/#7ED321/#FF6B6B）

### Step 8：附件（必须执行，不得跳过）
把最终产物打包成 zip，放到第五部分作为附件。

**必检清单（逐项过）：**
- [ ] 这次做课过程中有没有产生最终产物？（skill文件/模板包/代码/配置文件/数据表等）
- [ ] 如果有产物，是否已经打包成 zip？
- [ ] zip 是否已经插入飞书文档？（用 `lark-cli docs +media-insert --doc <doc_id> --file <zip路径> --type file` 插入）
- [ ] 插入后是否用 `block_move_after` 移到了第五部分对应位置？（不能只堆在文档末尾）
- [ ] 附件前面是否加了说明文字："这个是什么、怎么用"？

**操作步骤：**
1. 用 `Compress-Archive` 把产物目录打包成 zip
2. 用 `lark-cli docs +media-insert --type file` 插入文档（会插到末尾）
3. 用 `lark-cli docs +update --command block_move_after` 把附件移到第五部分
4. 在附件前面插入一段说明文字

**如果没有产物：** 在第五部分写清楚"学完你能自己做出来什么"，并说明本次无附件。不得跳过检查直接说"没有附件"。

## 输出格式

```
✅ 课程已生成

【课程标题】XXX
【课程定位】付费大课 / 认知笔记 / 案例拆解
【飞书文档链接】XXX

【结构概览】
0. 结果先行：可复制的提示词/模板
1. 开篇：痛点钩子
2. 第一部分：概念和误区
3. 第二部分：X轮用户↔豆包联动对话记录
4. 第三部分：X个真实踩坑
5. 第四部分：方法论
6. 第五部分：X个附件
7. 结尾：差异化总结

【待你确认】
- 文字版内容有没有要改的？（配图已自动完成，不需要确认）
```

## 红线

- **必须结果先行**：文章最开头必须先放可复制的提示词/模板/核心结论，不能铺垫半天还没给读者能拿走的东西
- **必须有用户↔豆包联动对比**：对话记录不能只写用户说的话，每一轮都必须有豆包的回复内容，形成一来一回的对比；禁止用"AI做了什么"的旁白叙述代替豆包回复本身
- **必须用真实对话记录**，不能编造
- **对话记录必须用代码块展示**，禁止用叙述性文字转述用户原话和 AI 回复
- **配图自动执行**，不等用户确认（除非用户明确要求先不配）
- **自动脱敏**，敏感信息不能出现在课程里
- **不改变用户真实意图**，只是整理成课程结构
- **禁止手动操作步骤**：课程内容（尤其是行动号召、方法论）里不能出现让读者手动操作工具的步骤（如"打开XX创建XX""手动配置""点击XX按钮"），必须强调用AI/豆包工作自动化完成。生成后必须逐段检查，发现手动操作表述立即改掉
- **禁止为凑结构虚构内容**：7段式是参考结构，不是硬指标。真实对话里有几个坑就写几个，有几个阶段就写几个。提炼的经验必须明确标注"经验提炼"，不得伪装成"真实踩坑"。真实性检查（Step 3.5）必须执行，不得跳过
- **附件必须放入文章**：只要做课过程中产生了最终产物（skill文件/模板包/代码等），必须打包成 zip 并插入飞书文档第五部分，不得遗漏。附件检查（Step 8）必须执行，不得跳过
- **不清楚的先问**，不要自己猜
