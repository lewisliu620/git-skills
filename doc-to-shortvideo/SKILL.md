# Doc to Shortvideo（课程文档转短视频流水线）

本 Skill 是编排器，本身不写文案、不生图、不剪辑，只负责按流水线串联下游 Skill，并在两个关键节点强制停下来让用户拍板。

## 快速开始

读文档提炼 → 写脚本 → **【停点1】脚本确认** → 素材准备 → **【停点2】素材方向确认** → 配音+生视频 → ffmpeg剪辑合成 → 上传飞书交付。

## 核心职责

1. 按流水线顺序串联下游 Skill，每个环节用最合适的工具。
2. 在「脚本确认」和「素材方向确认」两个节点真停，等用户点头再往下走。
3. 全程贯穿去AI化标准，不让人一看就觉得是AI生成的。
4. 缺数据用占位符，不编造文档里没有的内容。
5. 对外动作（发布到平台）只走到预览，不替用户点确认。

## 六步主干流程

1. **读文档提炼**：用 `lark-doc` 读取飞书课程文档内容；用 `doubao-critical-reading-companion` 深度提炼核心观点、金句、结构，确定视频主线和时长。
   - 时长判断：短知识点 → 15-60秒；完整章节 → 1-3分钟；长课程精华 → 3-5分钟。
   - 不停，自动执行完进下一步。

2. **写脚本**：用 `doubao-shortvideo-writing` 写短视频分镜脚本，包含：口播文案、画面描述、字幕要点。写完过 `doubao-human-signal` 去AI味，让文案更像真人说话。

3. **【停点1】脚本确认**：把分镜脚本给用户看，问"脚本方向对不对，要改哪里"。确认前禁止下一步。
   - 用户要改 → 改完再确认
   - 用户说OK → 进下一步

4. **素材准备**：
   - 优先用文档里已有的配图和素材（节约token）
   - **文章/清单类内容先走 lewis-article-to-cards**：把飞书文档转成3:4组图卡片（Swiss/Editorial双视觉系统，HTML渲染+Playwright截图，0积分），卡片直接作为视频帧源
   - 不够的地方用 `image_search` 搜网络真实素材补充（巨头logo、产品截图、数据图表、办公场景图）
   - 所有图片统一裁切成竖屏9:16（1080x1920），不拉伸不变形，居中适配
   - 关键数据/数字要做成可动画的素材（数字滚动、柱状图增长、箭头动画）
   - 用 `byted-mediakit-image` 处理图片尺寸、格式、压缩

5. **【停点2】素材方向确认**：正式生成视频前，先给2-3个画面方向草稿让用户挑。每个方向写清：整体风格、画面色调、配图感觉。选定前禁止调用生视频工具。
   - 不满意 → 换方向再选
   - 选定了 → 进下一步

6. **配音+生视频**：
   - 配音：用 `seed-audio` 生成自然口语感配音，不要播音腔。
   - **多角色/去AI味（规范）**：有真人样音时走 A2A 模式——每个角色配一段 5~10 秒参考音频，`text_to_audio_plus` 的 prompt 里用 `@音频1`/`@音频2` 指定音色，语气跟着参考音走；用户说"没样音/用默认音色"时不阻塞，直接 T2A，但 prompt 必须写清"口语化、像朋友聊天、不要播音腔"，且在交付说明里标注"未使用克隆音色，后续补样音可重配"。
   - 视频片段：用 `seedance-25` 按分镜脚本生成视频片段。
   - 不停，自动执行。

7. **剪辑合成**：
   - 用 `byted-mediakit-editing` 做粗剪：音视频对齐、镜头按讲解内容逐段切换、转场。
   - 用 **本地 ffmpeg** 做最终合成：
     - **字幕（业界最佳实践，硬规范）**：半透明黑色圆角背景框 + 白色粗体字 + 黄色关键词高亮，每行≤8字，10条以内，位置在画面高度60%-78%安全区（避开顶部10%、底部18-20%、右侧12%平台UI）。不用描边（Outline），用阴影+半透明背景框。浅色背景卡片上白色字必须加黑底框，否则看不清。详见下方「字幕最佳实践」。
     - **背景音乐（免积分方案）**：用ffmpeg合成三和弦环境音（220+277+330Hz sine + 低通1200Hz + aecho混响），音量0.35低于配音。单调sine波是反模式，必须用和弦+混响。免版权BGM可从Pixabay/Free Music Archive下载。
     - **动态效果**：关键数字/图表要有动画（滚动、增长、弹出），不能全程静态图片轮播。
     - **Ken Burns 防抖（硬规范）**：zoompan/横移前先把源图 4 倍超采样（1080x1920 → 4320x7680），再让 zoompan 直接输出 1080x1920——否则坐标取整为整像素，慢速推镜会肉眼可见地微跳（ffmpeg trac #4298）。
     - **faststart（硬规范）**：最终混流命令必带 `-movflags +faststart`，否则上传平台后封面/缩略图全黑（详见 shortvideo-mp4-finalize skill）。
     - 调整音量、输出 mp4
   - 不满意的单段/单条单独重做，不整体回退。

8. **交付**：
   - **默认落本地项目目录**，不传飞书（用户明确要求上传时再用 `lark-drive`）。
   - 给用户视频文件路径，说明视频时长、分辨率、走了哪条流程、调了哪些Skill。
   - 如果用户要求上传飞书，用 `lark-drive` 上传后给预览链接。

## 去AI化硬标准（贯穿全流程）

1. **配音要自然** —— 口语感，像朋友聊天，不要播音腔，不要机器味
2. **画面要真实** —— 优先真实截图、数据图表、实拍感素材，不要AI生成的塑料感画面
3. **节奏要像人做的** —— 有快有慢，重点地方停顿，不要匀速匀速再匀速
4. **字幕要专业** —— 半透明黑底框+白字粗体+黄色关键词高亮，每行≤8字，位置在安全区内，跟配音同步，不要花里胡哨的字体和动画（详见「字幕最佳实践」）
5. **脚本要去AI味** —— 必须过 `doubao-human-signal`，不要那种"首先、其次、最后"的八股文
6. **视觉要动起来** —— 关键数字、图表要有动画效果（滚动、增长、弹出），不能全程静态图片轮播
7. **素材要丰富** —— 不能只用文档里的几张图，要搜网络真实素材补充，跟着讲解内容逐段切换镜头

## 逐帧动画渲染规范（推荐方案，0积分）

当内容是"观点/清单/方法论"类（非实拍/非产品演示）时，**优先用PIL逐帧渲染**，不调生视频模型。这是对标爆款视频"滚动层层递进"效果的核心技术。

### 架构：长页面思维，不是卡片轮播

把所有内容做成一个逻辑上的长页面（如1080×15360），每个section占1080×1920。视频=逐帧crop这个长页面，模拟向上滚动。

**不要做的**：8张静态卡片+Ken Burns缩放轮播——视觉单调，对标视频都是滚动+内部动画。

### 每个section的内部动画（必须有，不能静态）

| 元素类型 | 动画方式 | 帧数(25fps) |
|---|---|---|
| 大数字（如"50"） | 从0滚动到目标值，ease_out | 20-25帧 |
| 标题 | 从下方滑入+淡入，ease_out | 15-25帧 |
| 列表项 | 逐条弹出/左滑入，间隔10-15帧 | 每项8-12帧 |
| 标签/色块 | 宽度从0展开 | 5-10帧 |
| 分割线 | 长度从0展开 | 5-10帧 |
| CTA文字 | 脉冲缩放（sin波±5%） | 循环 |
| 箭头 | 上下弹跳（sin波） | 循环 |

### section间转场：滚动而非淡入淡出

用ease_in_out向上滚动：当前section上移移出，下一section从下方移入。每段转场45帧（1.8秒），每个section停留80帧（3.2秒）。

**关键：转场目标帧必须跟section内部起始帧一致。** 用f=3作为转场目标帧，section内部也从f=3开始渲染——否则转场结束后会从f=3跳回f=0，出现空白闪帧。

### 渲染流程

```
1. 为每个section写render函数，接收帧号f(0-82)，返回PIL Image
2. 预渲染每个section的f=3（转场目标）和f=82（转场源）
3. 逐帧渲染：section内部f=3..82 → 滚动转场45帧 → 下一个section...
4. 所有帧存PNG → ffmpeg -framerate 25 -i frame_%05d.png 编码
```

## 字幕最佳实践（业界共识，硬规范）

来源：抖音/视频号剪辑师共识 + Recapo/Versly/OpusClip安全区研究。

1. **背景框**：半透明黑色圆角矩形（BackColour=&HC0000000, BorderStyle=3, Outline=8），浅色背景上白字必须加，否则看不清。
2. **文字**：白色粗体（Noto Sans CJK SC Bold），字号48px（画面高度2.5%），不用描边用阴影。
3. **关键词高亮**：黄色（&H0000FFFF），跟主题色（蓝/橙）区分开，不用主题色做高亮。
4. **字数**：每行≤8字，用\N分行，最多2行。能断句就断，不超10字。
5. **条数**：10条以内，每条至少显示2秒，减少切换频率。
6. **位置**：MarginV=360（画面约81%高度），在卡片内容区下方、底部署名上方。安全区：避开顶部10%、底部18-20%、右侧12%。
7. **颜色总数**：≤2种（白+黄），不用渐变和纹理。

## 踩坑经验（血泪教训，必看）

### ffmpeg类
1. **xfade转场的input参数必须拆开**：`-i clips/clip_01.mp4 -i clips/clip_02.mp4`，不能写成`-i "clip_01.mp4 clip_02.mp4"`。
2. **scale滤镜不能同时接两个输入**：`[1:v][0:v]scale=...`会报错，必须先单独scale再overlay。
3. **Ken Burns必须4倍超采样**：否则zoompan坐标取整为整像素，慢速推镜肉眼可见微跳（ffmpeg trac #4298）。
4. **faststart必加**：`-movflags +faststart`，否则上传平台后封面全黑、网页预览要等完整下载。
5. **单帧输出加`-update 1`**：ffmpeg 7.x+抽单帧png必须声明，否则报"image sequence pattern"错。

### 字幕类
6. **描边（Outline）效果差**：白色字+黑色描边在浅色背景上仍看不清，业界用阴影+半透明黑底框。
7. **字幕位置跟卡片底部署名重叠**：MarginV太小会压到卡片底部的"刘易斯Lewis·洞见AI漫步"文字，需调到360以上。
8. **蓝色高亮跟IKB蓝主题色混淆**：关键词高亮用黄色，不用主题色。

### 逐帧渲染类
9. **section起始帧跟转场目标帧不一致导致空白闪帧**：转场用f=3做目标帧，section内部必须也从f=3开始渲染，不能从f=0开始。
10. **f=0帧元素全空白**：所有动画都从f>0开始，f=0时画面几乎空白。转场结束后接f=0会闪一下空白。解法：统一从f=3开始。

### 环境类
11. **Playwright必须用系统chromium**：`executable_path="/usr/local/bin/chromium-browser"` + `--no-sandbox`，bundled chromium未安装。
12. **edge-tts云环境403**：Linux容器连不上微软speech服务，本地Windows可用。
13. **faster-whisper跟PyAV版本不兼容**：`metadata_errors`参数报错，改用openai-whisper。

## 红线

1. **两个停点必须真停**，不得连续执行；脚本未确认前禁止生成素材和视频。
2. **对外动作只走到预览**，不替用户点发布到抖音/视频号等平台。
3. **内容以文档为准**，不编造文档里没有的观点、数据、案例。
4. **去AI化是硬要求**，每个环节都要检查，不能做完了才发现"一眼AI味"。
5. 用户中途改主意时，立即停掉当前链条，复述新需求后再继续。
6. `references/` 为空时，不得假装懂品牌风格；用通用教育风格，并在交付说明里标注"未加载品牌语料"。
