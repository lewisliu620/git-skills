# Content Pipeline（内容创作编排器）

本 Skill 是编排器，本身不写文案、不生图，只负责按场景串联下游 Skill，并在两个关键节点强制停下来让用户拍板。

## 快速开始

**前置：内容日历**（每月/每周跑一次，决定发什么）→ 识别配方（A/B/C/D）→ 写母稿（写作时直接去AI味）→ **停点 1：母稿确认** → 多平台改写 → **停点 2：画面方向确认** → 配图（先搜图再画，核心2-3张）→ 交付。

## 核心职责

0. **内容日历规划**：用 `creator-content-calendar` 每月/每周产出内容日历和选题库，决定每天发什么、什么类型、什么节奏。
1. 按关键词把需求路由到 A/B/C/D 四种配方之一。
2. 驱动下游 Skill 产出母稿，并默认沉淀到飞书文档。
3. 在「母稿确认」和「画面方向确认」两个节点真停，等用户点头再往下走。
4. 缺数据用占位符，不编造客户名、数字、参数。
5. 对外动作（公众号发表、发邮件）只走到预览，不替用户点确认。

## 工作流（单篇文章执行）

1. **意图理解**：按关键词匹配 A/B/C/D 四种配方；模糊时一句话反问，不硬抛选题。
2. **写母稿（必须派单给下游skill，禁止自己写）**：
   - **派单前先读下游skill**：识别配方后，必须先 Read 对应下游skill的 SKILL.md，严格按它的流程和规范执行，不能自己瞎写。
   - **配方A（公众号/长文）派单给 `doubao-wechat-writing`**：
     1. 先 Read `doubao-wechat-writing/SKILL.md`，按它的路由判断文章类型（新闻热点/专业解读/故事纪实/认知观点/情感治愈）
     2. 再 Read 对应类型的 writing-style 文件（如 `references/writing-styles/professional-explainer.md`）
     3. 严格按该类型的写法、结构、语言要求写
     4. 产出必须包含：正文 + 封面图建议 + 备选标题（至少3个）+ 内容验真 + 运营策略建议
     5. 写作时直接按 human-signal 原则写（去模板腔、加人感、短句优先）
   - **配方B（小红书/脚本）派单给 `doubao-newmedia-writing`**：先 Read 它的 SKILL.md，按小红书笔记规范写
   - **配方D（复盘/汇报）派单给 `doubao-book-writer`**：先 Read 它的 SKILL.md，按长文档规范写
   - **派单失败红线**：如果因为任何原因没有走下游skill、自己直接写了文章，交付时必须明确告诉用户"这次没有走下游skill，是编排器自己写的，质量可能不达标"，不能假装走了完整流程。
   - 默认通过 `lark-doc` 存飞书文档；缺数据用【待补数据】占位，不编造。
3. **【停点 1】母稿确认**：把母稿给用户看，问"是否 OK，要改哪里"；确认前禁止下一步。
4. **润色**（已合并到写作，不单独跑）：写母稿时直接按 human-signal 原则写（去模板腔、加人感、短句优先），母稿确认后不单独再跑一遍润色步骤。只有用户明确说"润色一下/去AI味"才单独执行。
5. **多平台改写**（默认自动执行，不得自行跳过）：
   - 用户明确说"一稿多发 / 多平台 / 同步发公众号 / 知乎也发一版"→ 必须做多平台改写。
   - 用户只说单平台（如"写篇小红书"）→ **默认也生成公众号版**，标注为"可选分发版本"，存同一飞书文档的独立分区；只有用户明确说"只要小红书/不要公众号版"才跳过。
   - 公众号版遵守用户已有的公众号文案规矩（正文不提微信号/价格/硬引流，引流走关键词回复，配图用逻辑图/流程图）。
   - 小红书版直接按已知格式追加（标题≤20字、正文≤1000字、有emoji、纯文本可复制），不单独读 multiplatform-rewrite skill。
   - 这一步不停，自动执行完进停点 2。
6. **【停点 2】画面方向确认**：正式生图/生视频前，先给 2-3 个方向草稿让用户挑。每个方向必须写清：整体风格、封面设计、内页规划、配色方案。用 `interaction.ask` 让用户选，不要只在文本里列选项。选定前禁止调用任何生图/生视频工具。
7. **正式生成配图**（按需配图，核心 2-3 张，不追求数量）：
   - **第一步先搜图**：能用现成图就不自己画。产品界面截图、官方配图、数据图先用 `image_search` 搜，搜到合适的直接用。
   - **搜不到再自己画**：逻辑图、流程图、对比表、步骤图这类需要精确中文文字和统一配色的，用 HTML/CSS + headless 浏览器截图。
   - **HTML 模板库复用**：常用图型（流程图/对比表/步骤图/卡片/矩阵）的 CSS 固定，每次只改文字内容，不重新写 CSS。模板存在本 skill 目录 `references/html-templates/` 下。
   - **配色必须按主题匹配（不再固定教育色卡）**：渲染配图/贴图前，先识别文章主题/行业，读 `references/color-scheme-by-scenario.md`，按匹配优先级（用户明确指定 > 关键词精确匹配 > 语义主题匹配 > 兜底科技色系）选定对应场景色卡，用该场景的主色/辅助色/强调色/中性色（HEX 值）渲染。正文禁用纯黑 `#000000`，高亮面积 ≤10%。账号有品牌色时品牌色优先。
   - **配图数量**：每篇文章核心 2-3 张关键图（开头一张+核心章节 1-2 张），不是每篇固定 5 张。内容简单就配 2 张，内容复杂最多 4 张。
   - 氛围图 / 插画 / 封面视觉 / 人物场景 → 走 `creative-design` / `seedream-50`（但优先判断能不能搜图解决）。
   - 视频 → 走 `seedance-25` / `creative-video`。
   - 不满意的单张重做，不整体回退。
   - **配图位置硬规则**：每张图必须插在对应章节的旁边（该章节标题下面 1-2 段的位置），**绝对不能全部堆在文档末尾**。流程图放在"流程/步骤"章节旁边，对比表放在"对比/前后变化"章节旁边，概念图放在"概念解释"章节旁边。
   - **配图插入正确方法**：不要用 `+media-insert` 直接插末尾（那个命令只能插到最后）。正确做法是：先写好 markdown 正文，用图片 file_token 在 markdown 里引用（`![描述](file_token)`），然后用 `overwrite` 命令一次性写入文档，这样图片自动出现在正确位置。
8. **贴图随发（发布公众号/小红书文章时自动执行，不停点）**：
   - 文章定稿后，自动从文章提炼：标题 + 核心要点（3-5 条）+ 金句 + 真实数据（有则用，没有就不出对应卡）。
   - 用 `references/html-templates/` 卡片模板生成 3-4 张贴图（封面卡 / 要点卡 / 金句卡 / 数据卡），配色用本文章主题匹配的场景色卡（同上一条规则），不用 AI 生图（信息图类 AI 出中文会乱码）。
   - **一套资产两用，不重复出图、不增加积分消耗**：贴图优先复用该文章已生成的配图资产（裁切/重组/只改文字），同一批图既是文章配图也是贴图；只有文章没有可用配图资产时才用模板新渲染。模板渲染为本地 HTML/CSS + headless 截图，不消耗 AI 生图积分。
   - 发布时自动带上：小红书 → 贴图作为图文笔记的图片（标题≤20字+正文+标签）；公众号 → 正文插入贴图。某平台不发布则跳过该平台贴图。
9. **交付**（必须全部完成，缺一不可）：
   - 飞书文档链接**必须通过 `present_files` 正式交付**，不得只在聊天文本里贴链接。
   - **配图不逐张交付**：图全部插入飞书文档后，只交付文档链接一次。用户要单张图时再单独发。
   - 公众号只走到预览不发表；汇报加 `html-report-deck`。
   - **附发布操作指南**：说明目标平台的发布限制（如小红书不支持一键图文复制，图片需手动从相册上传），给出"复制正文 → 上传图片 → 填标题 → 发布"的具体步骤。
   - 最后一句话告诉用户走了哪条配方、调了哪些 Skill。
