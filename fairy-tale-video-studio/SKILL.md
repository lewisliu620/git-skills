# 童话故事多产品流水线

把童话故事做成多角色配音的竖版动态绘本视频，并同集产出绘本 / 声音故事 / 图文笔记 / 公众号文 / 家长手册，豆包工作流 + 本地 ffmpeg 为主，零视频生成额度；可选即梦 CLI（dreamina-canvas）补位升级。

## 快速开始

八步出产：角色确认 → 写故事剧本 → 分段配音 → 转写取真实时间戳 → 按情节补图 → 合成视频（可选即梦补位）→ 绘本页/音频/衍生文案 → 质检交付。

```
角色确认(唯一人工) → 故事+剧本 → 6 段配音(WAV/MP3) → analyze_audio+note +transcript 取逐句时间戳
→ 缺情节图则锚点 image_edit 补图 → windows.csv + build_episode.ps1 出视频
→ [选配] 即梦 CLI：真动镜头/绘本超清/局部重绘（jimeng_mode 开关）
→ 绘本页 PDF/EPUB + 声音故事 mp3 + 图文/公众号/家长手册（自动）
```

## 核心职责

1. 按三幕框架生成 500-700 字儿童故事 + 分角色剧本（旁白+2-3 角色，同角色音色描述逐字复用）
2. 分段多音色配音、EBU R128 响度归一化、拼接
3. 用逐句真实时间戳（非估算）切画面窗口，成片时间 = 配音时间戳 + 3s 片头
4. 保证台词提到的实物元素与关键动作有对应画面（缺图基于核心锚点 image_edit 补）
5. ffmpeg zoompan 动态绘本合成：烧字幕、合音频、片头片尾
6. 同集多产物：绘本页（每页≤2句 + 封面封底 + 固定版式 EPUB/PDF）、声音故事（复用音轨 +0 成本）、图文笔记 / 公众号文 / 家长手册（自动文案）
7. 角色确认门：每集开场仅一次人工确认（出场角色或新角色卡），其余环节零打断
8. 即梦 CLI 补位（选配，V1.3）：按 `jimeng_mode` 开关调用 dreamina-canvas 做真动镜头 / 绘本图超清 / 局部重绘，豆包仍为主通道

## 工作流程/详细规则

### 第 0 步：开工确认门（唯一人工节点，V1.4 起，由"角色确认门"扩展）
每集开工一次性确认 6 项，确认后第 1-7 步全自动零打断；成片验收抽查不算生产人工：

| # | 确认项 | 说明 | 曾出错的教训 |
|---|---|---|---|
| 1 | 出场角色/新角色卡 | 按资产包列出角色 | — |
| 2 | 配音语言 | 全中文 / 全英文 / 中英混（默认问清，不擅定） | 第 1 集国风英语错配成中文为主 |
| 3 | 字幕格式 | 纯中 / 纯英 / 双语（英文上中文下等） | 双语字幕须明确主次 |
| 4 | 英文难度（如英文配音） | 不限制 / 启蒙简化（3-6 岁）/ 3-12 岁不限 | 难度影响台词与时长 |
| 5 | 动效档位 jimeng_mode | none / motion / hd / full（见第 6 步表） | 静态 Ken Burns≠用户预期"人物会动" |
| 6 | 成本来源 | 即梦免费额度 / 付费积分（预算上限） | 免费额度 MVP 需用户授权才用 |

- 新角色：AI 草拟角色卡（画面描述 + 音色描述，套用画风锚点）→ 用户确认 → 写入资产包角色卡区后逐字复用。
- **角色卡规格写法（正例+反例）**：任何外观属性必须写明"必须/禁止"，防止歧义。例：脸盘必须雪白（禁止黑色毛发覆盖面部）；黑毛只允许出现在耳尖/眼周/四肢；年龄感明确（Q 版幼态，禁止成人脸）。首张锚点图即按规格验收，不合格当场重生成，不进入下游。

### 第 1 步：故事与剧本
- 用 fairy-tale-studio 的三幕框架与年龄段规则（3-6 岁，500-700 字，2-3 分钟）。
- 输出：三幕故事 + 6 段左右分角色剧本（旁白独立段，对话按"角色聚集"分组）。
- 儿童安全红线：无暴力/恐怖/迷信/烟酒/涉性/危险模仿，结局温暖正向（见 `references/quality-checklist.md`）。
- **历史考据门（V1.5 起，典故/历史类故事强制）**：成稿前必须考据典故原文与时代器物形制，把"实体清单"写进剧本头，出图与配音前逐条核对：
  - **常识通名门（V1.9 起强制，先于史实考据执行，防"起错名"类常识错误）**：**故事名/典故名/主角名/成语必须与大众认知一致，出稿前先核验大众通名**（第 1 集教训：业界都叫"司马光砸缸"，我却按史实原文"击瓮"起了"司马光砸瓮" → 全链路返工）。规则：**大众通名 = 用户可见文本的唯一基准（标题/旁白/字幕/词卡一律用"砸缸"）**；史实原文（"光持石击瓮破之"）只作**画面形制参考**（器口内收的瓮形画面），禁止把考据词汇带进用户可见文本。核验动作：出稿前对典故名/人物名做一次检索确认（"司马光砸缸"通名），列出通名 vs 原文对照（如：通名"砸缸"/原文"击瓮"，可见文本用通名）。V1.8 曾致返工：标题/配音/字幕/词卡全用"瓮"被用户驳回。**改规则时必须同步删除旧冲突条款**（V1.8 升级时残留"中文旁白用'瓮'"一条导致规则自相矛盾——本行即清理产物）。
  - 典故原文（如《宋史·司马光传》"群儿戏于庭……光持石击瓮破之"）：器形为**瓮**（口小肚大、器口内收、瘦高），画面按瓮形绘制；动作是**击瓮壁侧面**破壁放水救人，不是砸向水面或瓮口（画面砸向水面 = 史实错误，曾致返工）。
  - 实体清单三项：容器形制（瓮形画面/缸通名）、道具年代（宋代蹴鞠=皮革缝线充气球，不是现代皮球；石块=孩童能抱起的中小石）、人物年龄（事件参与者=7 岁左右孩童，不是大人——"谁在做什么"必须匹配）。
  - 英文保持 jar（"Sima Guang and the Water Jar"）配瓮形画面；中文侧全用"缸"（缸沿/大水缸/缸壁/词汇"缸，jar"），与常识通名门一致。
  - **史实角色分工铁律（V1.7 起强制，典故类故事必须写明"谁落水/谁施救"）**：《宋史》"一儿登瓮，足跌没水中，众皆弃去，光持石击瓮破之"——**落水者 = 玩伴（"一儿"/一个小伙伴），施救者 = 主角（司马光），主角全程在瓮外**。曾致返工：剧本写"他爬了上去……他掉进瓮里了"+"画面用主角形象画爬瓮沿"→ 观众误读"司马光落水"，与史实冲突。**出稿前剧本头必须写清：{落水者=？，施救者=？，主角位置=瓮外}，三者缺一不可。**
- **静态检查门（V1.9 起强制，出稿后配音/出图前执行，把检查从"用户验收后"前置到"生成前"）**：剧本与分镜定稿后，对剧本文本跑一遍自动化检查清单，任一项红 → 改稿后重跑，**禁止带红进配音/出图**（检查后置 = 返工成本最高点，曾致：重影 1 次、命名 1 次、重配音 4 段、双版重合成 2 次）：
  - □ 通名核验：全局检索禁用词（"瓮"等旧名）清零；典故名与人名与大众通名一致
  - □ 常识/事实：人物关系、故事名无违背常识项
  - □ 人称锚定：遇险/施救句的"他/她/我"前文有明确主语
  - □ 段落去重：相邻段无重叠的开场/场景句
  - □ 实体清单：容器/道具/人物年龄逐条写出
  - □ **画面状态锚点（V1.16 起强制，防"物体空间关系出图后才暴露"）**：剧本正文与分镜表必须写死每个关键画面的**实体空间关系**——物体相对位置/接触关系/物理合理性（例：球=**停在缸沿上、与缸沿接触、静止**，禁止悬浮空中/禁止在瓮内水中；瓮=落地地面；人物=站缸外地面；石头=砸瓮身侧面非水面）。**正文台词动作与分镜画面状态必须闭环一致**（第 1 集教训：剧本画面核对表写"蹴鞠滚向瓮脚"，但后续情节需要"球停在缸沿上玩伴爬沿够球"——状态锚点缺失 → shot03 出图球悬浮空中/缸内，用户驳回"球没在规定的位置、在空中、在缸里，是两个相对的物体"）；缺锚点=禁止出图
  - □ 角色分工：{落水者、施救者、主角位置}三者明确
  - □ 词汇段：中文版片尾中英结合（"缸，jar"式），英文版纯英文
  - □ 语速：台词按 100-120wpm 估算成片时长在 90-150s（估算值仅预检，切点仍以真实时间戳为准）
- **双版本剧本（V1.5，lang_mode=dual）**：同一剧情写英文版 + 中文原音版两套台词，句意对应但不逐字翻译；中文版天然服务家长侧（公众号/喜马拉雅/自建平台），英文版服务启蒙侧，两版共用一套分镜。

### 第 2 步：多角色配音
- 按开工确认门的"配音语言"执行；英文配音先小样实测（1 句试听）锁定音色再全量生成。
- **配音语言门（V1.10 起强制，防"英文配音变中文"事故）**：开工确认门选定配音语言后，TTS 台词必须与该语言一致——英文版所有台词全英文（禁止中文/拼音混入，除专有名词 Sima Guang/Xiaojiu 外），中文版全中文；段生成后转写抽查语言一致性，混入错误语言立即重配该段（曾致返工：全英文配音的集，实际成片配了中文）。
- 每段 ≤120s；同一角色所有段落复用完全一致的音色描述前段。
- **语速与信息密度规则（V1.5 起强制）**：TTS prompt 必须写"语速从容缓慢、句与句之间自然停顿、词与词之间清晰"；目标实测语速约 100-120wpm（3-12 岁启蒙舒适区）。**严禁为压时长减少信息密度**（句子可以短，内容不许砍）；时长由配音实际时长决定（90-150s 自然达成，不预设上限截稿）。转写后抽测 1 处语速，过快（>140wpm）则降速重配。
- 每段 loudnorm 归一化：`loudnorm=I=-16:TP=-1.5:LRA=11`，再 concat 拼接。
- 平台 text_to_audio_plus 下载的 `.bin` 实为 WAV，改名 `.wav` 后处理。
- **中文词汇段中英结合（V1.6 起强制，词条用"缸"V1.8）**：中文原音版片尾词汇段必须中英结合领读——"**缸**，jar。石头，stone。勇敢，brave。聪明，clever。朋友，friend。"（第一词随通名规则用"缸"，禁止"瓮"），禁止只念中文（用户曾指出"中文词汇段纯中文"不符合启蒙定位）；字幕同段中英并排；词卡图文字与配音一致（"缸 jar"）。英文版词汇段保持纯英文。
- **双版本配音（V1.5，lang_mode=dual）**：英文轨 + 中文轨各 6 段并行生成（同一角色两版音色描述逐字复用）；各自拼接后分别转写取时间戳；中文版可先配后听，因中文 TTS 语速天然快于英文，句长控制更重要。
- **台词人称锚定（V1.7 起强制）**：涉及落水/遇险/施救动作的"他/她"**必须前文明确锚定**——起句不得直接"他爬了上去"，必须"**一个小伙伴**爬上了瓮沿 / **One little friend** climbed up"；落水呼救的"I/我"只属于落水者。曾致误读：无锚定的"他爬上去→他掉进瓮里"让观众以为主角落水。
- **段落去重门（V1.7 起强制，防"音频复读"）**：剧本分段时**开场句/场景句只在所属段出现一次**（禁止把上一段开头的"一天，XX 和朋友们在院子里玩……"再写进下一段）；拼接前逐段核对相邻段文本无重叠；拼接后转写全轨，**若 ASR 出现同一台词两次 → 定位段文件重叠并修复**（曾致返工：段2 复读段1 开场，v1 起就埋下、v2 转写更清晰才暴露）。
- **段文件验证（V1.7 起强制）**：段文件命名可能与内容错位/重叠（v1 曾出现 seg_cn3 实含"爬瓮沿+救命+快想想"三段内容）；**新生成或复用的每段，先单独转写验证内容与命名一致、无重复，再进拼接**；全轨转写必须人工抽读一遍确认剧情线完整无复读。

### 第 3 步：转写取真实时间戳（铁律，禁止按语速估算）
- 拼接好的配音上传 → `analyze_audio` 生成智能纪要 → `lark-cli note +transcript --note-id <vc-node-id>` 拿逐句带时间戳转写稿。
- 时间戳为配音流内 0 基；**成片含片头（adelay 与片头时长一致，默认 3s，紧凑版 1.5s），画面窗口与字幕时间 = 时间戳 + 片头时长**。
- **音频开头静音检测门（V1.12 起强制，防"前 5-6 秒无声空转"）**：拼接后的配音轨**先跑 `silencedetect=n=-45dB:d=0.4` 检测开头静音**（TTS 拼接常自带 1-3.5s leading silence；第 1 集实测开头 3.46s 纯静音），若开头有静音 **必须裁掉**（`-ss <静音结束点> -i 音频`），再按片头做 adelay；否则片头 adelay + 音频自带静音会叠加成 5-6s 空转被用户驳回。**片头时长与节奏**：片头标题 3s 太长，紧凑版 1.5s（标题 drawtext enable 与 adelay 同步 0-1.5s，窗口/字幕时间戳同步前移）；成片无声段 = 片头时长，禁止额外静音。
- 换算示例（第 1 集）：配音 00:29"围巾可暖和了" → 成片 32s；配音 00:58"围巾借你" → 成片 61s。

### 第 4 步：按情节出图（9:16 竖版，1536×2730）
- **出图前检查门（image-gate，V1.10 起强制，借鉴业界最佳实践）**：出图前先写**分镜表**（一镜一行：台词 | 画面元素 | 角色及其服饰 | 动作/站位 | 场景 | 情绪 | **实体空间关系**），再逐镜核对后才生成：
  - **实体空间关系字段（V1.16 起强制）**：分镜表每镜必须有一列写清"物体 A 与物体 B 的相对位置/接触关系"（球↔缸沿：球停在缸沿上、与缸沿接触；人↔缸：站缸外地面；石头↔缸壁：砸缸身侧面）；**禁止"两物体无接触关系的相对独立"描述**（第 1 集 shot03 教训：prompt 未约束球的位置 → 画成"球悬浮空中/在缸里"，画面里球与缸是两个无逻辑关系的相对物体）。
  - **prompt 空间关系强约束（V1.16 起强制）**：变化块必须写入空间关系硬约束英文原句（例："the ball rests ON the rim of the water jar, touching the rim, resting still"）+ 空间负向（"no ball floating in mid-air, no ball inside the water"）；要求新画面时同时否定旧错误态。**空间关系约束优先级 = 动作约束**（先定"东西在哪、跟谁接触"，再写"谁做什么"）。
  - **出图后空间关系验收（V1.16 起强制）**：每张图 Read 大图时**先核对实体空间关系**（球是否与缸沿接触、人物是否站地面、砸缸是否砸缸身侧面）再核对角色/画风；空间关系不符**当场拒收重出**，禁止进合成（本集 shot03 球悬浮=出图阶段即可发现，不应到成片才被用户指出）。
  - **逐镜角色特征核对**：每个分镜的 prompt 必须包含本镜所有出场角色的特征块（业界：分镜 prompt 漏角色特征→生成偏差，如"第二个镜头没提小松鼠特征"）；角色特征从角色卡**逐字复制**，禁止缩写/改写。
  - **prompt 模板系统**：固定块（角色卡特征 + 画风锚点 + 质量标签，逐字复用）+ 变化块（本镜动作/背景/情绪），禁止混入旧画面术语（如定稿"柔和水彩风"后不得改"3D 卡通"）。
  - **一镜一画**：每个 prompt 只画一个冻结帧瞬间，禁止在一条 prompt 里写连续动作序列（"去图书馆→找书→读→离开"式句式直接违反）。
  - **负向提示精炼**：只写本图实际出现的失败模式，具体化（"身体在缸轮廓内"优于"错误"）；每次只加一个负向词，保持参考图与设置不变对比效果（业界：5-10 条精确负向词优于冗长清单）。
  - **文字类图强制 OCR**：词卡/含字图生成后必须 OCR（Read 或转写）核对文字逐字正确，不合格当场重出（第 1 集词卡"瓮 jar→缸 jar"先例）。
  - **验收前置**：**画面内容/色调/风格全部确认后才动视频生成积分**（业界：先图后视频，图不合格就动视频=双重浪费）。
- 先出 1 张核心锚点图（主角团同框+主场景），后续所有镜头基于锚点 CDN URL 用 `image_edit` 延展，保证角色一致；生成一张立即 `present_files` 交付一张（doubao-creative-design 规则）。
- **批量并行出图（V1.9 起，效率项）**：同批独立镜头用 `image_edit` 的 request_list 一次并行生成多张（≤10 张/批），生成后逐张 Read 大图目检，再逐张 `present_files` 交付（交付仍一张一交，不合并）；连续镜头优先排在同一批（同一参考图 URL 复用，减少上下文与往返）。
- 逐句核对：台词提到的实物（帽子/围巾/球…）必须出现在画面；关键动作（递、接、够、追…）要有专属镜头。缺就补 1 张，不硬撑。
- **画面实体校验（V1.5 起强制，比"实物入画"更严一层）**：出图后核对"**谁**在做什么、**往哪里**做"：
  - 谁：人物身份必须匹配台词（跑走的是孩童群像，不是大人；施救者是孩童，不是大人代劳）；
  - 做什么/往哪里：动作指向必须正确（击瓮壁**侧面** → 破口在缸壁、水从破口横向涌出；不能砸向水面或瓮顶，此为史实错误曾致返工）；
  - 道具形制：蹴鞠（皮革缝线）不是现代球；石块中小可抱起不是巨石；容器按第 1 步实体清单（瓮形）。
  - 关键动作图（砸/递/接/跑）出图后用 Read 大图目检一次再进合成，不合格当场重出，不硬撑进成片。
- **空间自洽（V1.6 起强制，V1.16 统一为"球停在缸沿上"状态锚点，道具位置与人物动作同一逻辑）**：铁律 = **物体停在哪，人物就去哪够它**。第 1 集教训：球在瓮脚地面、画面却画"孩子扒瓮沿够球"→ 空间矛盾返工 2 次；**定稿状态锚点 = "球停在缸沿上（与缸沿接触、静止）→ 孩子爬缸沿够球 → 失足坠瓮"**（球必须与缸沿接触，禁止悬浮空中、禁止在瓮内水中——用户驳回"球没在规定的位置、在空中、在缸里，是两个相对的物体"）。
  - **人物站位铁律（V1.8 起强制，防"人进缸内/透过缸壁重影"）**：**任何站立的角色（尤其施救者）必须站在缸体外的地面上**——双脚踩地面、与缸体有清晰前后空间距离、身体完全在缸体外轮廓之外；**禁止角色身体出现在缸体轮廓内、禁止透过缸壁看到角色身体、禁止与缸体重叠的半透明效果**（曾致返工：shot05 v4 蓝衣司马光被画进缸内、透过缸壁可见 → 观众反馈"人物重影到缸里"，v5 重绘修正）。出图 prompt 写空间否定式："站在缸外石板地面、身体完全在缸体外轮廓之外、禁止透过缸壁可见、禁止重影"；出图后 Read 大图核对缸内外分明。
  - **画面-角色一致性（V1.7 起强制，防"主角被误认为落水者"）**：落水者与施救者（主角）在画面里**形象必须可区分**——不同服饰颜色（本集：落水玩伴=鹅黄汉服，司马光=浅蓝汉服）、不同站位；禁止用主角形象画爬瓮沿/落水者。出图前先写清"图里谁是落水者、谁是主角、各自服饰"，出图后核对两角色可一眼区分；同框时两人都要出现且分开。曾致返工：shot05 用司马光形象画爬瓮沿 → 观众误读司马光落水。
  - **生图 prompt 用空间否定式（V1.16 更新）**：写"球停在缸沿上、与缸沿接触、静止；禁止悬浮空中、禁止落入水中、禁止滚落地"——image_edit 对"球卡在/停在缸沿"类指令理解差（曾连续 3 次画进水面、画成悬浮空中，用户驳回"球在空中、在缸里"），**必须用"接触关系肯定式 + 旧错误态否定式"**（"rests ON the rim, touching the rim" + "no floating in mid-air, no inside the water"）一次成功；要求新画面时同时否定旧错误态（"不落入水中、不溅水花"）。
  - **人物合理性**：够球者必须站瓮外地面/扒沿踮脚（禁止画进瓮内泡水，曾画错 1 次）；落水与被救者、施救者身份年龄必须与台词一致；同一空间前后镜头道具位置不得漂移（球在瓮口沿 → 够球也在瓮口沿）。
  - **业界通例（坠瓮叙事成因）**：儿童故事坠瓮通因 = "爬瓮沿/登高处够物失足"（绘本通例：个子最高的孩子双手抓住缸沿、脚一蹬、手探到缸内）；本集"球停瓮口沿 → 爬沿够球 → 失足"即按此设计，掉入前的画面成因必须自洽，禁止无成因空降落水。
- 每集基准 6-8 张：锚点 1 + 场景远景 1 + 角色特写 2-3 + 关键情节 2-3。

### 第 5 步：合成（低内存三步 + 时长预校验 + 进程卫生，V1.4 修订）
- **窗口-图版本一致性检查门（V1.11 起强制，合成前必须执行，防"改版混用旧图"事故）**：改过任何图（重绘/换终稿/改词卡）或改过标题文字后，**合成前必须逐一核对 windows.csv 里引用的文件名 = 02_图片 里的最新终稿文件名**，并核对片头 drawtext 标题文字 = 最新通名。本次第 1 集英文版事故根因：v7 合成时 w09-w11 仍引用 `shot05_司马光扒瓮沿_v4.jpg`（重影问题图，v5 终稿未进表）、w21-w24 仍引用 `shot15_单词卡_v2.jpg`（旧"瓮 jar"词卡，v3"缸 jar"未进表）、片头标题残留"砸瓮"——三处都是"修正素材已交付、但窗口表没同步"的版本管理事故，被用户以"英文版怎么还有穿模/你不是修复了吗"驳回。**检查动作**：合成命令发出前，用命令 grep windows.csv 的 image 列逐一比对终稿文件名；片头标题用 grep 核验不含旧名（"瓮"）。**禁止"图已修好但 windows.csv 没更新"的状态进入合成。**
- **先校验再合成**（防第 1 集尾窗不足教训）：按真实时间戳建窗后，用命令核验 `窗口总时长 ≥ 3 + 配音时长 + 3`（片头 3s + 配音 + 片尾 3s）；不足则延长最后窗口（静止卡）后再进合成。三者（窗口总和 / 配音时长 / 字幕末条时间）任一不满足即重排 windows.csv 与字幕，不硬合成。
- **低内存三步法**（系统 RAM 紧张时必用；避免 -12 内存不足）：
  1. 逐窗 zoompan 生成 + concat（`-c copy`，零内存压力）；
  2. 烧字幕：`-filter_script <ass路径文件>` + `-c:v libx264 -preset veryfast -crf 23 -threads 1`（单线程低内存）；
  3. 合音频：**先纯音频预处理** `-af "adelay=3000|3000,apad=whole_dur=<总时长>" -c:a aac` 出 m4a，再 `-map 0:v -map 1:a -c:v copy -c:a copy` 双 copy mux（禁止用 filter_complex adelay 直合音频，实测会触发重编码路径导致内存耗尽）。
- **低内存兜底（V1.11 起强制，build_episode.ps1 已知缺陷）**：`build_episode.ps1` 的最后一步（filter_complex 烧字幕+adelay 合音频直出成片）在系统内存不足时必现 `-12 (Cannot allocate memory)` 失败，且失败后输出的成片是**损坏半成品**（mp4 无 moov，无法播放，文件看似巨大）。**遇 -12 或成片无法播放：不要重跑全流程，直接手动三步法收尾**——(a) 确认 `full_silent.mp4` 已生成且为新时间戳（本次 13:00 前旧 silent 是旧图版本，勿复用）；(b) 单独烧字幕 `-filter_complex_script fc_sub.txt`（ass 路径必须绝对，冒号转义 `C\:`）+ `-preset veryfast -threads 1` 出 `sub_v8.mp4`；(c) 音频预处理 `adelay=3000|3000,apad=whole_dur=<总时长>` 出 m4a；(d) 双 copy mux **必须加 `-t <视频总时长>` 截齐**（apad 的 whole_dur 按 filter 链起点计，音频会多出约 3s 尾音，不加 -t 会导致片尾 3s 黑屏有音无画）。
- **合成效率（V1.9 起，效率项）**：①**同图连续窗合并**——相邻多窗若为同一张图且动效相同，合并为一段长 zoompan（区间拉长、动效延续），减少 ffmpeg 启动次数与中间文件（22 窗可压到 12-14 段）；②**逐窗并行**——机器内存允许时多进程并行生成各窗（每窗独立 ffmpeg，互不依赖），比串行省 40-60% 墙钟；③**复用 silent**——**仅改字幕/音频（图集与标题未变）时跳过逐窗重跑**，直接复用 build 目录的 full_silent.mp4 烧新字幕+新音轨（本次英文 v6→v7 因标题也改才全量重跑，纯字幕/音频微调可省 60% 合成时间）；④双版 silent 在内存允许时并行生成，互不争抢时串行兜底。
- **进程卫生**：任何 ffmpeg 后台任务结束后，检查并清理残留 ffmpeg 进程（残留进程会拖慢整机 IO、导致其他命令超时）；任务被终止时一并杀子进程。
- 参数一律绝对路径（build_episode.ps1 的 ReadAllLines 走 .NET API，相对路径会被解析到 cwd 而失败）；concat list 用绝对路径+正斜杠；读 UTF-8 文件用 Read 工具或显式 UTF8 编码（PS 5.1 Get-Content 默认 ANSI 显示乱码，仅显示问题不重写文件）。
- 片头（标题 drawtext 0-3s）+ 片尾预告卡（3s 静止，计入总时长）。
- **双版本合成（V1.5，lang_mode=dual）**：同一图集 + 两套 windows 表（各按本版配音真实时间戳 +3s 切窗）+ 两套双语 ASS（版式一致：英文在上、中文在下）。先并行生成两版 silent → 各烧各字幕 → 各合各音轨 → 两成片；图集/锚点零重复成本，边际成本仅配音+合成。中文版标题副题注明"中文版"。命名：`<集名>_第N集成片_英文版_v4.mp4` / `_中文版_v1.mp4`。

### 第 6 步：即梦 CLI 真动/超清补位（按开工确认门档位执行）

`jimeng_mode` 在开工确认门里定档（默认 none）：

| 开关 | 含义 | 单集预估 |
|---|---|---|
| `none` | 纯 Ken Burns，不调用即梦 | +0 |
| `motion` | 关键镜头 1-3 个真动（Seedance 图生视频，替换对应窗口的 zoompan） | +2-4 元 |
| `hd` | 绘本图智能超清 4K/8K（绘本导出前对封面+正文图批量 upscale） | +2-3 元 |
| `full` | motion + hd | +4-6 元 |

执行要点：
- **即梦调用前检查门（jimeng-gate，V1.10 起强制）**，按序通过才允许消耗任何积分：
  1. **图先验收**：本镜画面（内容/色调/风格）已在第 4 步验收通过，不合格图禁止送视频生成（业界共识：先图后视频，图错就动视频=积分双倍浪费）；
  2. **预算预检**：调用前核对本次计划消耗（免费额度余额 / 付费积分上限），超预算或需授权时停下报用户批准（即梦计费：**调用成功才计费**；会员生成图片免费、视频按 15s 约 90 积分消耗，实时价以 `schema`/`model list` 为准）；
  3. **首帧锁定**：图生视频首帧/参考必须用已验收镜头图（画布节点或 `--ref`），禁止文生视频替代已有图（图生清晰度/光影显著优于文生，业界实测）；
  4. **分段小步**：真动只做 1-3 个关键镜头、每段短时长（业界：分段生成，1 段失败总消耗 < 直接生成整段 15s 的成本；失败只重抽该段，不整段重来）；
  5. **生成后验收**：产物时长与对应时间窗吻合、角色无漂移、动作符合台词；不合格只重做该段。
- 调用走已安装 `dreamina-canvas`（C:\Users\Administrator\bin，命令以 `schema`/`model list` 实时结果为准，不凭记忆拼命令）；生成前 `auth status` 核对登录，需授权或积分确认时停下来问用户（即梦登录会过期，每集重核）。
- **免费额度 MVP（成本来源=免费额度时）**：先 `auth status` 确认有免费额度 → 用免费档/低档位模型生成 1-2 个关键镜头验证效果 → 达标后再按需加量；任何付费积分消耗前停下报用户批准。
- 真动镜头：先 `model list --type video` 选 Seedance 类模型，样片模式低成本跑通再生成成片；用画布节点/`--ref node:<node-id>` 引用锚点图保证角色一致；产物下载到本地后再与 ffmpeg 主流程拼接（替换对应时间窗，窗口总时长仍须覆盖 3+配音+3）。
- 超清：`model list --type image` 找 upscale 能力，对绘本封面（1600×2400）与正文页图升 4K/8K，替换进 PDF/EPUB 导出源。
- 局部重绘（可选）：修图/补元素时用 inpaint 类能力替代 image_edit 补位。
- 豆包仍是主通道：文本/配音/锚点生图/流程不变；即梦只做上述补位，避免全面切走导致角色锚点漂移。

### 第 7 步：多产物产出（V1.2 起，全自动）
- **绘本页**：画面窗 ↔ 绘本页一一对应；每页正文 ≤2 句（10-20 字/句）；封面（系列 Logo+集名+教育点）+ 版权页 + 10-12 页正文 + 封底（下集预告）。导出：**固定版式 EPUB（KF8）+ 打印级 PDF**；竖版 9:16 单页（与视频图共用）或 4:3 跨页（视频用 Ken Burns 裁 9:16），全系列二选一固定。
- **声音故事**：直接复用拼接好的配音音轨（+0 token），可选 ffmpeg 混 BGM（音量低于旁白 -20dB）；输出 `第N集_声音故事.mp3`（320kbps）+ 复用绘本封面（1600×2400）；按真实时间戳切分章起点。**双版本时出中/英两个 mp3**（喜马拉雅/小宇宙/自建平台音频矩阵）。
- **图文笔记**：绘本页 3-6 张拼图 + 一句教育点文案 + 互动提问（小红书）。
- **公众号文**：故事文字版（复用剧本）+ 插图 2-3 张 + 教育点解读段；正文不提微信/不放价，引流走评论区/自动回复（用户硬规矩）。
- **家长手册**：本集教育点 + 3 个延伸问题 + 1 个亲子活动 + 给家长的 1 句话提示。
- **双语版（可选开关）**：页面级翻译 → 英文 TTS 二次配音 → 双语版视频/音频。

### 第 8 步：质检与交付
- 按 `references/quality-checklist.md` 逐项验收；音频与画面逐句抽检。
- **交付前音画抽检（V1.10 起强制，量化）**：成片交付前抽 3-5 个关键帧（含片头标题、关键动作段、词卡段、片尾），逐帧核对：画面与对应时间戳台词一致、字幕文字正确（含"缸"非"瓮"通名）、标题/副题正确；发现不符先定位是图、字幕还是窗口排布问题，修复后重抽该帧再交付（第 1 集抽帧 QC 先例：shot05 重影、词卡"缸 jar"、片头"司马光砸缸"均靠抽帧发现/确认）。
- **成片时长对齐检查（V1.11 起强制）**：交付前用 `ffmpeg -i 成片` 核对容器 Duration = 视频窗口总时长（如 157.32s）；若容器时长比窗口总时长多 ~3s，说明音频 apad 尾音溢出（合音频未加 -t 截齐），片尾 3s 将有音无画，需重 mux 截齐后再交付。
- **字幕布局规范（V1.14 起强制，借鉴业界最佳实践）**：双语字幕统一放**画面下方安全区**（禁止英文顶置、禁止中英一顶一底远离）；**英文（主语言）在上、中文在下两行紧贴**（MarginV：EnSub≈243 / CnSub≈60，Alignment=2 底部居中，白字 + 黑描边 4 + 微阴影，MarginL/R=60）；**断行规则**：英文行 ≤40 字符、中文行 ≤24 字，在语义断句处用 \N 换行（长句不拆必然横向溢出，1080px 宽 40-42px 字号容不下 60+ 字符长句）；烧字幕后抽帧 OCR 验证：无横向溢出（文字框不贴画面 0/999 边）、英文在上中文在下、多行段（4+4 行）无重叠。
- **音画对应验证门（V1.15 起强制，借鉴业界最佳实践）**：**窗口与字幕时间戳必须以配音真实语音边界为基准，禁止按脚本整点粗分**。流程：配音完成后先对裁静音轨跑 `ffmpeg silencedetect`（n=-40dB,d=0.6）+ 转写逐字稿（analyze_audio），得到每句真实起止（语音段边界），据此建 windows.csv 与字幕时间轴（成片时间 = 语音时间 + 片头 adelay 秒数，如 1.5s）；交付前抽帧必须同时验证**画面内容 ↔ 该时间点字幕台词 ↔ 该时间点语音内容**三者一致（第 1 集 v11 事故复盘：时间轴为脚本粗分，句 6-8"滑倒落水/I can't get out"实际语音 57.6-69.3s 时画面仍停在扒缸沿（w09-w11 显示至 67.5s），句 11"看到石头/捡起/用力砸"语音 83.8-97.7s 时画面还在惊慌/镇定，句 12"水流出/获救"语音 98.9-105.6s 时画面还在砸缸——落水/砸缸/获救三段画面滞后 6-10s；重建后 v12 五段抽帧（30/60/95/100/120s）画面-字幕-语音三者对齐）。
- **字幕时间轴重映射规则（V1.13 起强制）**：ASS 时间戳整体偏移（如 -1.5s）必须保持 Dialogue 行字段结构 `Dialogue: Layer,Start,End,Style,Name,MarginL,MarginR,MarginV,Effect,Text`——**Start/End 各占一个字段，禁止在字段值前后加多余逗号/空格**（第 1 集 v9 事故：转换时给 End 加了前导逗号，变成 `0:00:02.00,,0:00:06.00` 双逗号，Start/End 字段错位，ASS 解析失败整条字幕不显示）；转换后**必须抽查前 3 行 Dialogue 格式**（字段数=10、无空 End）再进入烧字幕。
- **抽帧验收必须 OCR 字幕（V1.13 起强制）**：交付前抽帧不仅看画面，**必须核对 OCR 结果同时含字幕文字**——中英双语版应出现顶部英文 + 底部中文两行（v9 事故复盘：v9 抽帧 2.5s/50s OCR 无字幕文字却未发现，直到用户"字幕又没了"才定位；字幕缺失在抽帧阶段即可发现，验收项必须含"字幕文字出现"）。
- 成片 `present_files` 交付，命名 `<集名>_第N集成片.mp4`；改版用 _v2/_v3 递增，不覆盖。
- 若开启即梦补位，额外核对：真动镜头时长与对应时间窗吻合、超清图与原图角色一致（无漂移）。

### 第 9 步：批量发布到视频号（V1.18，Tabbit CLI 驱动，一次发完 N 集×双版本）

用 `scripts/publish-videos.ps1` 把本集（或本批次多集）的成片一次性发布到视频号「小九竹林故事屋」，中/英文版各自独立发布，中文版在前、英文版在后。

- **配置**：`scripts/publish-config.json` 按数组顺序写每个视频 `{path, desc, shortTitle, publishBtn}`；`desc` 含故事简介+账号介绍（小九竹林故事屋：每天一个中英双语国学故事，陪孩子听世界，陪家长省时间）+语言说明（全英文配音+中英双语字幕，适合3-12岁英语启蒙）+话题（#成语/典故名 #EnglishStory #国学启蒙 #亲子英语 #中英双语）；`shortTitle` 必须 ≥6 字（如"司马光砸缸英文版"），英文版标题注明"英文版"。
- **前置**：Tabbit 浏览器已启动；视频号助手（channels.weixin.qq.com）已扫码登录——脚本先自检，未登录会打印提示并退出，不会误传。
- **执行**：`powershell -File publish-videos.ps1`；逐集：打开发布页 → `setInputFiles` 上传 → 轮询等待编辑页就绪（textarea/contenteditable 出现，单集约 1-4 分钟）→ 填描述（textarea 优先）+ 短标题（第一个可见 input）→ 点"发表"（`button:hasText(publishBtn)`，处理确认弹窗 accept）→ 跳转视频管理列表 `platform/post/list` 验证标题出现。
- **验证**：脚本对每集输出 published-verified / published-pending-confirm；视频号有数分钟审核期，列表可见即成功。
- **回写**：全部发完后把进度表该集「发布」字段改为"视频号已发"（中英两版都发完可标"全渠道已发"）、「总状态」置"已发布"，用 `lark-cli base +record-batch-update` 并回读确认。
- **坑点**：脚本必须纯 ASCII 源码（中文经配置 JSON 运行时注入，PS5.1 无 BOM UTF-8 脚本按 ANSI 解析会乱码断句）；cmd.exe 调 tabbit 时 stderr 有环境变量横幅，函数内临时降级 `$ErrorActionPreference="Continue"` 再恢复（`2>$null` 在嵌套命令中不生效）；发布页登录态会过期，每批次先 `goto post/create` 自检 URL 是否含 login；视频上传超时上限约 4 分钟，超时判失败并跳过该集继续下一集。**视频号助手 2026-10 改版实测（V1.18 固化）**：①页面为 wujie 微前端，编辑区渲染在 shadow DOM——`page.locator` 可穿透（textarea/input/contenteditable 都能定位），但 `page.evaluate(document.querySelectorAll)` **不穿 shadow 会漏**，页面就绪/取文本一律用 locator 或 `tabbit.observe`；②上传控件是 `input[type=file]`（存在于 shadow，locator 找得到），上传前**轮询等待其出现（编辑区渲染约 10-20s，别等 3s 就判 no-file-input）**；③描述区是 contenteditable div（不是 textarea），填表遍历"可见"元素（`textarea:visible`/`input:visible`，页面有不可见的"商品链接"textarea 必须跳过）；④短标题是第一个可见 input；⑤"发表"按钮 `button:hasText(发表)` 点击后无确认弹窗（dialog=none 属正常）；⑥**验证列表用 `goto platform/post/list` 后截图目检**（列表内容在 shadow，`body.innerText` 只有导航骨架，getByText 也可能抓不到）；⑦发布成功后回写进度表「发布」=全渠道已发（中英都发完才标）。

## 红线

1. 不消耗视频生成额度：动态绘本永远用静态图 + zoompan 兜底；即梦补位（真动/超清/重绘）仅按 `jimeng_mode` 选配且需用户知情，不默认开启；免费额度/付费积分来源以开工确认门为准，付费消耗前必须停下报用户。
2. 不按语速估算切点；切点只信真实时间戳（analyze_audio 转写）；不为压时长减少信息密度（语速从容 100-120wpm，句间停顿充分，时长由配音定）。
3. 画面必须与台词情节对应：台词实物入画、关键动作有专属镜头，缺图必补；**场景空间自洽（物体停在哪、人物去哪够它；球腾空瓮口沿→扒沿够球→失足；禁止球在瓮脚却扒瓮沿）与人物合理性（站瓮外地面不泡水、孩童群像非大人）**；**史实角色分工（落水者=玩伴≠主角，施救者=主角全程瓮外）、台词人称锚定（遇险"他/她"前文必须锚定）、画面角色可区分（落水者与主角不同服饰/站位）**；典故类故事必须过历史考据门 + 画面实体校验（人物身份/动作指向/道具形制），砸缸砸的是瓮壁侧面不是水面。
4. **段落去重门**：剧本段与段内容不得重叠（开场句只出现一次）；新段/复用段先单独转写验证内容与命名一致再拼接；全轨转写抽读确认无复读。
5. 儿童安全红线一票否决（暴力/恐怖/迷信/危险模仿等），结局强制正向。
6. 同集同角色音色描述逐字复用，不漂移；画风锚点逐字复用；角色卡规格必须正例+反例写明。
7. 生成一张图立即交付一张（doubao-creative-design 最高优先级规则）。
8. 生产环节除"开工确认门"（含配音语言/字幕/难度/动效/成本 6 项）外零人工打断；绘本必用固定版式 EPUB（禁用流式版式）；衍生文案遵守平台合规（公众号正文不提微信/不放价）。
9. 即梦 CLI 命令/模型/积分一律以实时 `schema`、`model list`、`auth status` 为准，不凭记忆拼写；需积分批准或授权时停下问用户，不擅自超支。
10. 合成先做时长预校验（窗口总时长 ≥ 3+配音+3），低内存环境走三步法，禁止 filter_complex adelay 直合音频；后台任务收尾必查残留 ffmpeg 进程。
11. 发布到视频号一律走 `scripts/publish-videos.ps1` 批量脚本（Tabbit CLI），不手工逐集上传；短标题 ≥6 字、描述带话题、中英版独立发布；登录态过期先自检提示用户扫码，不硬闯。
